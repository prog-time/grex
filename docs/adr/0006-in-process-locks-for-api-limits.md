# 0006. Лимиты API защищены блокировками внутри процесса, сервер работает одним процессом

- **Статус:** Предложено (PR #46)
- **Дата:** 2026-10-14
- **Задача:** #39, PR #46

## Контекст

Публичный API ограничивает ключ: до 5 незавершённых задач `/v1/jobs`, до 500 мониторов, одна ссылка не больше одного раза. Проверка и запись шли без блокировки, и при одновременных запросах лимит обходился: в тесте из 20 параллельных запросов прошли 19 задач при лимите 5.

## Решение

- Проверка лимита и вставка выполняются под `asyncio.Lock` для этого ключа (`utils/locks.py`, `key_lock()`).
- Блокировки хранятся отдельно для каждого цикла событий: `asyncio.Lock` привязывается к циклу, в котором его впервые ждали (сервер работает в одном цикле, тесты создают новый на каждый тест).
- Сервер работает одним процессом (`python api.py`, один воркер uvicorn), поэтому блокировки внутри процесса достаточно.

## Альтернативы

- **Ограничение в базе** (уникальный индекс, `SELECT … FOR UPDATE`). В SQLite нет `FOR UPDATE`, а лимит «не больше N» уникальным индексом не выразить.
- **Распределённая блокировка в Redis.** Redis в проекте необязателен.

## Последствия

- Если запустить несколько воркеров или экземпляров сервера, лимиты снова станут обходимыми. Масштабирование потребует нового ADR (блокировка в Redis или другая база).
