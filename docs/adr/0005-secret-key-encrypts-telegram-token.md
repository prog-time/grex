# 0005. `admin.secret_key` шифрует токен Telegram, поэтому не меняется автоматически

- **Статус:** Принято
- **Дата:** 2026-10-14
- **Задача:** #32, PR #42

## Контекст

`admin.secret_key` из `data/settings.yml` используется дважды:
- подписывает cookie сессии админки (`SessionMiddleware`). Для входа достаточно, чтобы в сессии было поле `username`, поэтому известный ключ позволяет подделать вход;
- из него выводится ключ Fernet, которым зашифрован токен Telegram-бота (`services/secrets.py`).

В примере настроек стоял публичный `change-me-in-production-secret-key`, и `start.sh` копировал его в каждую новую установку.

## Решение

- При создании `data/settings.yml` из примера `start.sh` сразу записывает случайные `secret_key` и пароль администратора и показывает пароль в терминале. В этот момент ещё ничего не зашифровано.
- У существующих установок со стандартным ключом `start.sh` и сервер только предупреждают. Ключ автоматически не меняется: после смены сохранённый токен Telegram перестанет расшифровываться.
- Случайный ключ «в памяти» при прямом запуске `python api.py` не используется по той же причине: после перезапуска токен, сохранённый в этой сессии, стал бы нечитаемым.

## Альтернативы

- **Автоматически менять стандартный ключ у всех установок.** Молча ломает отправку оповещений в Telegram.
- **Отдельный ключ шифрования.** Развязал бы вход и шифрование, но требует переноса уже зашифрованных токенов. Можно сделать отдельным решением.

## Последствия

- Смена `secret_key` выкидывает всех из панели и требует заново ввести токен Telegram в «Настройки → Параметры мониторинга». Это описано в README и `RUNBOOK.md`.
- Нельзя добавлять новые данные, зашифрованные этим ключом, не учитывая, что его смена их потеряет.
