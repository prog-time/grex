# 0007. Версия приложения хранится только в файле `VERSION`

- **Статус:** Принято
- **Дата:** 2026-10-14
- **Задача:** #40, PR #43

## Контекст

Версия была вписана в `config.py` вручную. Релиз v1.0.1 вышел с версией `1.0.0` в API и логах: её забыли поднять.

## Решение

- Единственный источник версии: файл `VERSION` в корне. `config.py` читает его в `settings["soft_version"]`, оттуда версия попадает в `/openapi.json` и в каждую строку лога.
- `tests/test_version.py` падает, если `VERSION` меньше последнего тега `v*`. В CI задача `test` получает теги (`fetch-depth: 0`).
- Порядок релиза: PR с новым `VERSION` → слияние → тег и GitHub Release из `main`.

## Альтернативы

- **`git describe --tags`.** Не работает без `.git`: в архиве релиза и в Docker-образе.
- **`[project].version` в `pyproject.toml`.** Проект не устанавливается как пакет, `pyproject.toml` хранит только настройки инструментов.

## Последствия

- Забытое повышение версии ловит CI, а не пользователь.
- Повышать `VERSION` нужно отдельным изменением до создания тега.
