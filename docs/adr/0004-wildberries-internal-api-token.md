# 0004. Wildberries через внутренний API с антибот-токеном из браузера

- **Статус:** Предложено (PR #50)
- **Дата:** 2026-10-14
- **Задача:** #34, PR #50

## Контекст

В октябре 2026 Wildberries стал отвечать 403 на публичные JSON API, которыми пользовался парсер: `card.wb.ru`, `search.wb.ru`, `catalog.wb.ru`. Страница товара без проверки отвечает 498 (антибот). Цены стали доставаться только через браузер: 15-25 секунд на товар, а ссылки продавца за 1-2 минуты.

Что выяснено при исследовании:
- сам сайт берёт данные с `www.wildberries.ru/__internal/...` (`u-card/cards/v4/detail`, `catalog/sellers/v4/catalog`);
- после проверки в браузере появляется cookie `x_wbaas_token`;
- простой `fetch` из страницы с этим cookie получает 403, а HTTP-запрос через `curl_cffi` с этим cookie **и** заголовками браузера (`deviceid`, `x-requested-with`, `x-spa-version` и другими) получает 200, в том числе через прокси.

## Решение

- Браузер (Patchright, в отдельном процессе) открывается один раз, чтобы получить cookie и заголовки. Они кэшируются в памяти и в `data/wb_api_session.json`.
- Цены и ссылки продавца запрашиваются HTTP-запросами к `__internal` с этим токеном. При 401/403/498 токен обновляется один раз, и запрос повторяется.
- Одновременно токен обновляет только один запрос (блокировка на цикл событий), чтобы пакетный парсинг не открывал браузер на каждый товар.
- Старые способы (`card.wb.ru`, поиск, цены из DOM в браузере) остаются запасными.

## Альтернативы

- **Всегда брать цены из DOM в браузере.** Работает, но в 5-10 раз медленнее и держит слот браузера.
- **`fetch` изнутри страницы.** Без заголовков браузера получает 403, а с ними держит браузер открытым на каждый запрос.

## Последствия

- Товар разбирается за 2-5 с вместо 15-25 с, ссылки продавца примерно за 1,5 с.
- Зависимость от внутреннего, недокументированного API: Wildberries может сменить адреса или проверку в любой момент. Это должна замечать ночная проверка (`scripts/live_check.py`).
- При массовых параллельных запросах Wildberries может сбросить токен. Код получает новый, отдельные товары уходят в запасной путь.
