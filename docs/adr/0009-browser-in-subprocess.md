# 0009. Браузер для парсинга запускается в отдельном процессе и с окном

- **Статус:** Принято (решение было принято раньше, записано задним числом)
- **Дата:** 2026-10-14
- **Задача:** #54

## Контекст

Часть маркетплейсов отдаёт данные только настоящему браузеру: антибот-проверки, капча Яндекс Маркета, куки Ozon и MegaMarket. Парсер использует Patchright (форк Playwright, который хуже обнаруживается антиботами). Синхронный API Playwright нельзя вызывать внутри цикла событий FastAPI, а зависший Chromium не должен блокировать сервер.

## Решение

- Браузерные задачи запускаются через `BaseCrawler._run_in_process()` (`crawlers/base.py`): отдельный процесс `multiprocessing`, результат возвращается через очередь, по таймауту (`browser.timeout_seconds`, по умолчанию 60 с) процесс принудительно завершается.
- Число одновременных браузеров ограничено семафором (`browser.max_concurrent`).
- Браузер запускается с окном (`headless=False`) во всех 9 парсерах: так он реже распознаётся как автоматический, и пользователь может вручную пройти капчу.

## Альтернативы

- **Async API Playwright в основном процессе.** Зависший браузер или утечка памяти бьёт по всему серверу.
- **Headless-режим.** Проще для серверов, но чаще блокируется антиботами. Не проверялось систематически.

## Последствия

- На сервере без экрана нужен виртуальный экран: Docker-образ (PR #48) запускает приложение через `xvfb-run`.
- У пользователя на компьютере при парсинге ненадолго открываются окна браузера. Это описано в README.
- Функции, которые выполняются в процессе, должны быть `@staticmethod` и получать всё через аргументы, а скрипты, которые их вызывают, должны запускаться под `if __name__ == "__main__"`.
