# CLAUDE.md

Grex Parser: парсер карточек товаров с 9 российских маркетплейсов, мониторинг цен, веб-панель `/admin` и REST API `/v1`. Python 3.12, FastAPI, SQLite, Redis (необязателен), Patchright для браузерных парсеров.

## Перед задачей

1. [`rules/README.md`](rules/README.md): какие правила читать для вашего типа изменения.
2. [`ARCHITECTURE.md`](ARCHITECTURE.md): устройство системы и схемы. Перед изменением моделей смотрите [ERD](docs/architecture/erd.md).
3. [`docs/adr/`](docs/adr/): почему сделано именно так. Не «исправляйте» то, что описано в принятом ADR, без нового ADR.

## Процесс

Задача на GitHub → ветка `issues-N` от `main` → коммиты с префиксом `issues-N|` → PR с `Closes #N`. Подробно в [`CONTRIBUTING.md`](CONTRIBUTING.md). Для этого есть команды `/task_create`, `/task_branch`, `/task_complete`, `/task_submit`.

Не коммитьте в `main` и ветки без номера задачи. Не обходите хуки (`--no-verify`).

## Стек

Стек и правила его изменения описаны в [`rules/README.md`](rules/README.md#stack). Главное:

- **Не добавляйте зависимость, не заменяйте библиотеку и не вводите новый фреймворк ради удобства одной задачи.** Сначала объясните, зачем, какие есть альтернативы и что изменится. Решение согласуйте с владельцем и запишите в ADR.
- Версии в CI зафиксированы в `requirements-ci.txt`. После изменения `requirements*.txt` выполните `make lock`.

## Что легко сломать

- **Один процесс.** Не запускайте несколько воркеров uvicorn: лимиты API держатся на блокировках внутри процесса (ADR 0006), SQLite не рассчитан на запись из нескольких процессов.
- **Мониторы API и цели админки в одной таблице.** Каждый запрос админки к `parse_targets`, `price_snapshots`, `price_alerts` фильтруйте через `admin_owned()` / `not_api_owned()` (ADR 0003).
- **Схема базы.** Новая колонка в существующей таблице: модель + `_ADDED_COLUMNS` в `models/job.py` + ERD (ADR 0001).
- **`admin.secret_key`** шифрует токен Telegram: не меняйте его автоматически (ADR 0005).
- **Браузер в отдельном процессе:** функции для `_run_in_process()` должны быть `@staticmethod`, скрипты, которые их вызывают, запускаются под `if __name__ == "__main__"` (ADR 0009).
- **Не придумывайте адреса API и селекторы маркетплейсов:** только подтверждённые в коде или в сетевых запросах настоящего браузера.
- **Тесты не трогают настоящие `data/` и Redis:** используйте временную папку и подмену, как в `tests/test_admin_handlers.py`.

## Документация меняется вместе с кодом

Задача не завершена, пока не обновлено то, что изменилось. Перед PR ответьте на вопросы из [`rules/process/ai-workflow.md`](rules/process/ai-workflow.md#8-documentation-sync-checklist): меняются ли границы компонентов, модель данных, внешние интеграции, сценарии, нужно ли новое решение в ADR. Строку о заметном для пользователя изменении добавьте в раздел `Unreleased` в `CHANGELOG.md`.

## Отчёт после изменения

В конце каждой задачи коротко напишите (в ответе и в описании PR):

1. **Что изменилось:** какие модули, функции, таблицы, маршруты добавлены, удалены или переработаны.
2. **Как теперь работает:** ключевой сценарий, какие данные обрабатываются, как взаимодействуют затронутые части.
3. **Почему так:** ограничения, альтернативы, выбор. Если решение влияет на устройство проекта, ссылка на ADR.
4. **Как проверено:** какие тесты и проверки запускались и что показали. Отдельно: что **не** проверялось.
5. **Что осталось:** ограничения, риски, найденные проблемы, следующие задачи.

Не пересказывайте каждую строку диффа. Если в работе выяснилось что-то неочевидное (ограничение площадки, причина странного поведения), сохраните это в репозитории: в ADR, `RUNBOOK.md` или `rules/domain/`, а не только в переписке.
