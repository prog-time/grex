# Эксплуатация Grex Parser

Что делать в типовых ситуациях. Устройство системы описано в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск и остановка

| Действие | Команда |
|---|---|
| Запуск (первый раз ставит окружение, браузер и создаёт `data/settings.yml`) | `make run` или `./start.sh` |
| Остановка | `make stop` (ищет процесс на порту 8004) или `Ctrl+C` в терминале |
| Перезапуск | `make restart` |
| Проверка, что сервис жив | `curl http://localhost:8004/v1/health` |

При первом запуске `start.sh` придумывает пароль администратора и показывает его в терминале. Он же лежит в `data/settings.yml` (`admin.password`).

## Логи

- Всегда пишутся в терминал, где запущен сервис.
- Если в `data/settings.yml` стоит `debug.logging_in_file: true` (так в примере настроек), ещё и в `logs/ГГГГ-ММ-ДД.log`. Новый файл каждый день, хранятся 7 дней.
- Подробные логи: `debug.active: true` (заодно включает Swagger на `/docs`).

## Бэкап и перенос

Всё состояние лежит в папке `data/`: база `admin.db`, настройки, куки, прокси, отчёты. Для бэкапа остановите сервис и скопируйте `data/` целиком. Redis хранит только очереди и кэш, его бэкапить не нужно.

## Откат на прошлую версию

```bash
make stop
cp -r data data.backup
git fetch --tags
git checkout v1.0.2   # нужная версия
./start.sh
```

Схема базы только растёт (ADR 0001), поэтому старый код работает с базой от новой версии: лишние колонки он не трогает.

## Частые проблемы

### Сервер не стартует: `FileNotFoundError: data/settings.yml`

Файла настроек нет. `./start.sh` создаёт его сам. Если запускаете `python api.py` напрямую, сначала выполните `./start.sh` один раз или скопируйте `data/settings.yml.example` в `data/settings.yml`.

### Порт 8004 занят

`make stop` останавливает процесс на этом порту. Другой порт задаётся в `data/settings.yml`, `app.port`.

### Redis недоступен

Сервис работает, но фотографии товаров не скачиваются, а список прокси читается из файлов без кэша. В логе при старте: `Redis init failed`. Запуск на macOS: `brew services start redis`, в Docker: `docker run -d -p 6379:6379 redis:7-alpine`.

### Ozon: «Proxies with Russian IP addresses are required to access Ozon»

Ozon не отвечает на запросы не из России. Нужны российские прокси: впишите их в `data/proxy.txt` (`login:password@host:port`, по одному на строку) и включите `proxy.active: true` или добавьте в панели «Настройки → Прокси».

### Яндекс Маркет: открылось окно браузера и висит

Это капча. Решите её в открытом окне, после этого парсер сохранит куки в `data/ym_cookies.json` и продолжит. На сервере без экрана (Docker) решить капчу нельзя.

### Wildberries: цены не приходят или парсинг медленный

Публичные API Wildberries отвечают 403, данные берутся через внутренний API сайта с антибот-токеном (ADR 0004). Токен получается в браузере и хранится в `data/wb_api_session.json`.

- Если в логах повторяется `WB internal API HTTP 403` или `could not get an anti-bot token`: удалите `data/wb_api_session.json`, при следующем запросе токен получится заново.
- При получении токена ненадолго открывается окно браузера, так и должно быть.
- Если не помогает, Wildberries мог сменить адреса или проверку. Проверьте вручную: `.venv/bin/python scripts/live_check.py --only wildberries`.

### Площадка перестала парситься

Маркетплейсы меняют сайты без предупреждения. Проверка одной площадки на эталонном товаре: `.venv/bin/python scripts/live_check.py --only <площадка>`. Каждую ночь это делает workflow «Live check» на GitHub и при ошибке заводит задачу. Если эталонный товар пропал из продажи, замените его в `PRODUCTS` в `scripts/live_check.py`.

### Забыли пароль администратора

Он хранится открытым текстом в `data/settings.yml`, `admin.password`. Поменяйте значение и перезапустите сервис.

### В логе «SECURITY: 'admin.secret_key' is set to an insecure default value»

У установки стандартный ключ, с ним можно войти в панель без пароля. Смените его, учитывая, что тот же ключ шифрует токен Telegram-бота (ADR 0005):

1. `make stop`.
2. В `data/settings.yml` замените `admin.secret_key` на случайную строку, например вывод `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`.
3. `make run` и войдите в панель заново.
4. Введите токен Telegram-бота ещё раз в «Настройки → Параметры мониторинга»: старый расшифровать уже нельзя.

### В логе «SECURITY: the default API key from settings.yml.example is active»

Ключ API `4353456dfvbdfg34` из старого примера настроек известен всем. Создайте новый ключ в «Настройки → API-ключи», передайте его своим интеграциям и отзовите старый (он помечен «Небезопасный»). Поле `security.api_key` в `data/settings.yml` очистите.

### Потерян ключ API

Ключ хранится только в виде хеша, восстановить его нельзя. Создайте новый в «Настройки → API-ключи» и отзовите старый.

### Отчёт в Telegram не приходит

- Проверьте токен бота и получателей в «Настройки → Параметры мониторинга». Получатель должен хотя бы раз написать боту, иначе бот не может ему отправлять.
- Отчёт уходит по частоте получателя, а не при каждом изменении цены.
- В логе при успешной отправке: `Monitoring report delivered to N source(s)`.

### Задача API в статусе failed с «Interrupted by server restart»

Сервер перезапустился, пока задача выполнялась. Фоновые задачи живут в процессе сервера и после перезапуска не продолжаются, создайте задачу заново.

## Чего не делать

- Не запускайте несколько воркеров uvicorn или несколько копий сервера на одной базе: лимиты API и запись в SQLite рассчитаны на один процесс (ADR 0006, ADR 0001).
- Не удаляйте `data/admin.db` для «починки»: пропадут цели, история цен и ключи API.
