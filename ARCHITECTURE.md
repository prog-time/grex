# Архитектура Grex Parser

Короткий вход в устройство проекта. Подробности в схемах из [`docs/architecture/`](docs/architecture/), причины решений в [`docs/adr/`](docs/adr/).

## В двух словах

Grex Parser работает одним процессом Python: сервер FastAPI отдаёт веб-панель `/admin` и REST API `/v1`, а рядом в том же процессе крутятся фоновые задачи: планировщик мониторинга цен, задачи API и скачивание фото. Карточки товаров разбирают парсеры площадок из `crawlers/`. Где обычного HTTP-запроса мало, парсер запускает Chromium в отдельном процессе. Данные лежат в SQLite (`data/admin.db`), настройки и куки в файлах `data/`, очередь фото и кэш прокси в Redis, который необязателен.

## Как читать

Начните с контекста, чтобы понять границы системы, затем контейнеры: там видно, какой модуль за что отвечает. Компоненты и сценарии нужны, когда меняете парсеры или мониторинг. ERD смотрите перед любым изменением моделей в `models/`.

## Главные правила устройства

- **Один процесс.** Лимиты API защищены блокировками внутри процесса, SQLite не рассчитан на запись из нескольких процессов. Несколько воркеров uvicorn запускать нельзя без нового решения (ADR 0006, ADR 0001).
- **Цели админки и мониторы API в одной таблице.** Разделяет их `parse_targets.api_key_id`. Любой запрос админки к целям, истории цен и оповещениям фильтруется через `admin_owned()` / `not_api_owned()` (ADR 0003).
- **Схема базы только растёт.** Новые колонки добавляются через `_ADDED_COLUMNS`, миграций нет (ADR 0001).
- **Браузер в отдельном процессе.** Функции для него `@staticmethod`, их число ограничено `browser.max_concurrent` (ADR 0009).
- **Маркетплейсы меняются без предупреждения.** Парсер идёт от быстрого способа к медленному и не падает на первом отказе. Что сломалось, показывает ночная проверка `scripts/live_check.py`.

## Когда обновлять эти документы

Вместе с кодом, в том же PR, если меняется:

- граница компонентов, новый фоновый процесс или внешняя система: C4;
- таблица или колонка: ERD и `rules/database/schema.md`;
- порядок шагов в сценарии из `sequences.md` или набор состояний: соответствующая диаграмма;
- решение, которое влияет на устройство проекта: новый ADR.
