# Grex Parser

Grex Parser собирает данные о товарах с российских маркетплейсов и интернет-магазинов: название, артикул, цены и фотографии. Вы вставляете ссылку на товар в веб-панели, остальное он делает сам. Программировать не нужно.

## Поддерживаемые маркетплейсы

| Маркетплейс | Домены |
|---|---|
| Wildberries | `wildberries.ru`, `.by`, `.kz` |
| Ozon | `ozon.ru`, `.by`, `.kz` |
| Яндекс Маркет | `market.yandex.ru`, `.by` |
| MegaMarket | `megamarket.ru` |
| ММ (бывший KazanExpress) | `mm.ru` |
| Ситилинк | `citilink.ru` |
| ВсеИнструменты.ру | `vseinstrumenti.ru` |
| CDEK.Shopping | `cdek.shopping` |
| Бигам | `bigam.ru` |

---

## Что умеет

- Собирает карточку товара: название, артикул, обычную цену и цену со скидкой, фотографии, описание и характеристики.
- Следит за ценами. Сохранённые товары перепроверяются по расписанию, а по результатам строится график цены.
- Отмечает заметные изменения цены и присылает в Telegram Excel-отчёт с ценами и этими изменениями по расписанию, которое вы выбираете для каждого получателя.
- По ссылке на каталог или страницу продавца находит ссылки на все товары внутри.
- Обрабатывает большие списки: загрузите файл со ссылками, и они спарсятся за один запуск.
- Отдаёт данные по API, если сбор товаров нужно подключить к своей программе или сайту.

## Быстрый старт

Нужен компьютер с macOS или Linux и **Python 3.12+**. На Windows проект запускается через WSL или Git Bash. Как поставить Python, написано в [`docs/getting-started.md`](docs/getting-started.md).

1. Откройте терминал в папке проекта.
2. Запустите скрипт установки и старта:

   ```bash
   ./start.sh
   ```

   Скрипт сам создаст окружение и установит зависимости вместе с браузером для парсинга Ozon и MegaMarket. От вас ничего не требуется, просто дождитесь окончания.

3. Когда в терминале появится строка `API: http://localhost:8004`, сервис готов.
4. Откройте в браузере **http://localhost:8004/admin**. Это панель управления.

   Логин **admin**. Пароль `start.sh` придумает сам при первом запуске и покажет в терминале. Он же сохранён в `data/settings.yml` (`admin.password`), а сменить его можно в разделе «Настройки → Пользователи».

Чтобы остановить сервис, нажмите `Ctrl+C` в том же терминале. Чтобы запустить снова, ещё раз выполните `./start.sh`.

## Как пользоваться веб-панелью

Панель открывается в браузере по адресу `http://localhost:8004/admin`. Разделы в левом меню:

| Раздел | Для чего |
|---|---|
| **Главная** | Пара слов о продукте и ссылка на группу поддержки в Telegram. |
| **Цели** | Добавить ссылку на товар (одну или списком из файла) и запустить сбор данных. |
| **Извлечение ссылок** | Вставить ссылку на каталог или магазин продавца и получить ссылки на все его товары. |
| **Товары** | Собранные карточки товаров: поиск, фильтр по маркетплейсу, экспорт в файл. |
| **Мониторинг** | Включить слежение за ценой товара, посмотреть график или очистить мониторинг целиком. |
| **История задач** | Журнал запусков сбора данных: что получилось, что нет и почему. |
| **Поблагодарить автора** | Как поддержать проект: донат, звезда на GitHub, Telegram-группа. |
| **Настройки → Параметры мониторинга** | Подключить Telegram-бота и получателей регулярных отчётов о ценах. |
| **Настройки → Прокси** | Список прокси-серверов на случай, если маркетплейсы блокируют прямые запросы. |
| **Настройки → Пользователи** | Логины и пароли для входа в панель. |
| **Настройки → API-ключи** | Ключи для REST API: создать, отозвать, посмотреть, когда ключ использовался. |

Обычно всё начинается с раздела «Цели»: вставьте ссылку на товар и нажмите «Запустить». Карточка появится в «Товарах». Если хотите следить за ценой этого товара, включите его в «Мониторинге».

## Настройка

Параметры сервиса лежат в `data/settings.yml`. Значения по умолчанию рабочие, так что открывать файл не обязательно. Он понадобится, если вы хотите:

- сменить адрес или порт сервиса (`app.host`, `app.port`);
- подключить прокси: впишите их в `data/proxy.txt` по одному на строку в формате `login:password@host:port` и включите `proxy.active: true`;
- настроить Redis (`redis.host`, `redis.port`). Без Redis сервис работает, но фотографии товаров не скачиваются.

Все настройки описаны в [`docs/getting-started.md`](docs/getting-started.md).

## Возможные проблемы

| Проблема | Решение |
|---|---|
| Redis недоступен | Сервис запустится, но фотографии товаров скачиваться не будут. На macOS Redis запускается командой `brew services start redis` |
| Не находит браузер для Ozon/MegaMarket | Выполните `.venv/bin/patchright install chromium` |
| При первом парсинге Ozon/MegaMarket/Яндекс Маркета открывается окно браузера | Так и должно быть: через браузер парсер получает куки. В следующий раз окно не откроется |
| При работе с Wildberries ненадолго открывается окно браузера | Так и должно быть. Wildberries пускает к своим данным только после проверки в браузере, поэтому парсер иногда открывает страницу, чтобы её пройти, и окно закрывается само. Остальные запросы идут без браузера |
| `command not found: python` | Используйте `python3` или настройте алиас, как описано в [`docs/getting-started.md`](docs/getting-started.md) |

## Для разработчиков: REST API

Сбор данных можно подключить к своей программе через REST API. Интерактивная документация открывается по адресу `http://localhost:8004/docs`.

Все пути API начинаются с `/v1`. Старые пути без версии (`/parse`, `/parse/batch` и т. д.) пока работают, но считаются устаревшими, поэтому в новых интеграциях используйте `/v1`.

Запросам нужен заголовок `X-API-Key`. Без него работают только `/v1/health`, `/v1/marketplaces` и `/v1/parse/detect`. Ключ создаётся в веб-панели: «Настройки → API-ключи → Создать ключ». Панель покажет его один раз, поэтому скопируйте ключ сразу.

Поле `security.api_key` в `data/settings.yml` оставьте пустым. Оно нужно только при переходе со старых версий: непустой ключ один раз переносится в список ключей. Если в списке есть ключ с пометкой «Небезопасный» (`4353456dfvbdfg34` из старого примера настроек), его знают все, и его нужно отозвать.

### Эндпоинты

| Метод | URL | Описание |
|---|---|---|
| `GET` | `/` | Информация о сервисе |
| `GET` | `/v1/health` | Статус и uptime |
| `GET` | `/v1/marketplaces` | Список маркетплейсов |
| `GET` | `/v1/parse/detect?url=...` | Определить маркетплейс по URL |
| `POST` | `/v1/parse` | Парсинг одного товара |
| `POST` | `/v1/parse/batch` | Пакетный парсинг до 100 ссылок, ответ после обработки всех |
| `POST` | `/v1/jobs` | Фоновая задача на парсинг до 1000 ссылок |
| `GET` | `/v1/jobs` | Последние задачи этого ключа |
| `GET` | `/v1/jobs/{id}` | Статус, прогресс и результаты задачи |
| `POST` | `/v1/monitors` | Начать отслеживать цену товара |
| `GET` | `/v1/monitors` | Мои мониторы с последней ценой |
| `GET` / `PATCH` / `DELETE` | `/v1/monitors/{id}` | Монитор: посмотреть, поставить на паузу или сменить интервал, удалить |
| `GET` | `/v1/monitors/{id}/history` | История цен |
| `GET` | `/v1/alerts?since=...` | Изменения цен по моим мониторам |

### POST /v1/parse

```bash
curl -X POST http://localhost:8004/v1/parse \
  -H "X-API-Key: ваш-ключ" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://www.wildberries.ru/catalog/17386348/detail.aspx"}'
```

Ответ:

```json
{
  "success": true,
  "marketplace": "wildberries",
  "processing_time": 1.23,
  "data": {
    "title": "Название товара",
    "sku": "17386348",
    "original_price": 1500.0,
    "current_price": 1200.0,
    "images": ["https://..."],
    "source_url": "https://..."
  }
}
```

### POST /v1/parse/batch

```bash
curl -X POST http://localhost:8004/v1/parse/batch \
  -H "X-API-Key: ваш-ключ" \
  -H "Content-Type: application/json" \
  -d '{
    "urls": [
      "https://www.wildberries.ru/catalog/17386348/detail.aspx",
      "https://ozon.ru/product/example-123456"
    ],
    "concurrency": 2
  }'
```

- `urls`: список ссылок, не больше 100.
- `concurrency`: сколько ссылок парсить параллельно. По умолчанию `batch.concurrency` = 10, максимум `batch.max_concurrency` = 50.

Ответ придёт, только когда обработаются все ссылки. Большие списки удобнее отправлять задачами.

### Задачи: POST /v1/jobs

Задача принимает до 1000 ссылок. Сервер сразу отвечает `202` с `id` задачи и парсит ссылки в фоне. Прогресс и готовые результаты отдаёт `GET /v1/jobs/{id}`: запрашивайте его, пока `status` не станет `completed` или `failed`.

```bash
curl -X POST http://localhost:8004/v1/jobs \
  -H "X-API-Key: ваш-ключ" \
  -H "Content-Type: application/json" \
  -d '{"urls": ["https://www.wildberries.ru/catalog/17386348/detail.aspx"]}'

curl http://localhost:8004/v1/jobs/<id> -H "X-API-Key: ваш-ключ"
```

- `status` проходит путь `pending` → `running` → `completed`. Статус `failed` означает, что задача прервалась целиком, например из-за перезапуска сервера. Такую задачу создайте заново.
- `done` и `total` показывают прогресс. В `results` лежат результаты готовых ссылок в порядке запроса, в том же формате, что у `/v1/parse/batch`.
- Задачу видит только ключ, которым она создана. У одного ключа может быть до 5 незавершённых задач, следующая получит `429`.

### Мониторинг цен: /v1/monitors

Монитор перепроверяет товар по расписанию и записывает цену. Первая проверка запускается сразу после создания.

```bash
curl -X POST http://localhost:8004/v1/monitors \
  -H "X-API-Key: ваш-ключ" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://www.wildberries.ru/catalog/17386348/detail.aspx", "interval_seconds": 3600, "name": "Матрас"}'
```

- `interval_seconds` задаёт, как часто проверять товар. Если его не передать, берётся значение сервера (`monitoring.default_interval_seconds`). Меньше `monitoring.min_interval_seconds` поставить нельзя.
- `GET /v1/monitors` возвращает все мониторы ключа с последней ценой (`current_price`, `price_updated_at`) и результатом последней проверки (`last_status`).
- `PATCH /v1/monitors/{id}` меняет только переданные поля. `{"active": false}` ставит монитор на паузу, `{"interval_seconds": null}` возвращает интервал по умолчанию.
- `DELETE /v1/monitors/{id}` удаляет монитор вместе с историей цен.
- `GET /v1/monitors/{id}/history` отдаёт точки цены от старых к новым.
- `GET /v1/alerts?since=2026-10-06T10:00:00Z` отдаёт изменения цены сильнее порогов сервера (`monitoring.drop_percent` / `rise_percent`), новые сверху. Передавайте в `since` время прошлого запроса, и придут только новые.

Мониторы видит только их ключ, в веб-панель они не попадают. Одну и ту же ссылку один ключ добавить дважды не может (ответ `409`), а всего у ключа может быть до 500 мониторов. Если ключ отозвать, его мониторы остановятся.

### Пример на Python

```python
import requests

API_URL = "http://localhost:8004"

response = requests.post(
    f"{API_URL}/v1/parse",
    headers={"X-API-Key": "ваш-ключ"},
    json={"url": "https://www.wildberries.ru/catalog/17386348/detail.aspx"},
)

data = response.json()
if data["success"]:
    product = data["data"]
    print(product["title"], product["current_price"])
```

### Как устроен проект

Один процесс Python: FastAPI отдаёт веб-панель и REST API, рядом работают планировщик мониторинга, задачи API и скачивание фото. Карточки разбирают парсеры площадок, а где обычного запроса мало, запускается Chromium в отдельном процессе. Данные хранятся в SQLite, настройки и куки в `data/`, очередь фото в Redis.

Схемы (C4, база данных, сценарии) собраны в [ARCHITECTURE.md](ARCHITECTURE.md), причины решений в [docs/adr/](docs/adr/).
